# LitSearch v0.6.0 Roadmap

## Goal

LitSearch v0.6.0 expands the stable v0.5.0 architecture with additional
scholarly retrieval sources, improved cross-source metadata handling,
metadata enrichment, and more explicit source capability semantics.

The architectural principles established in v0.5.0 remain unchanged:

- centralized retrieval pipeline
- uniform Paper model
- centralized cross-source deduplication
- shared retrieval logic between search and export where applicable
- connector-independent architecture

## Release Scope

The implementation scope for v0.6.0 is now frozen.

The release focuses on functionality already implemented during the v0.6.0
development cycle. Features that were originally listed as planned or under
evaluation but have not been implemented are not release blockers and are
deferred beyond v0.6.0 unless explicitly stated otherwise.

Before v0.6.0 can be released, the remaining release-level validation must be
completed and the release documentation must be finalized.

## Evaluated but not pursued

### CORE

CORE was evaluated as an additional retrieval source but was not integrated.
The available trial/API conditions and observed rate limits were not considered
suitable for LitSearch.

---

## Deferred beyond v0.6.0

### BASE

BASE remains a candidate retrieval source, but its evaluation and possible
integration are deferred beyond v0.6.0. BASE is not a release requirement for
v0.6.0.

Future evaluation should consider:

- API availability and stability
- licensing and terms of use
- metadata quality and completeness
- rate limits and operational constraints
- suitability for LitSearch's connector and deduplication architecture

If accepted in a future development cycle, integration should include:

- connector implementation
- All Sources integration
- participation in central deduplication
- validation of search, pagination, export, detail pages, All Sources, and deduplication

Crossref and DOAJ result-window pagination regressions were identified during
release-level validation. Crossref now declares and enforces its 10,000-record
result window, while DOAJ's existing 1,000-record result-window capability is
enforced by pagination. Direct requests beyond those windows are clamped to the
last accessible page. The fixes were validated with targeted regression tests,
the full non-integration suite, the integration suite, and manual
running-application checks, and were merged in PR #93.

## Performance and regression validation

- [x] Evaluate representative search and All Sources behavior against the
      available performance baseline evidence
  - The existing v0.5.0 performance investigation documents the representative
    workload and configuration but contains no quantitative timing results.
    A numerical v0.5.0-to-v0.6.0 latency comparison is therefore not possible.
  - Three cold v0.6.0 All Sources runs were measured with
    `ALL_SOURCES_CANDIDATE_LIMIT=2000`. Total elapsed times were approximately
    17.46 s, 5.96 s, and 2.35 s (median approximately 5.96 s).
  - External source latency dominated the observed variability. Internal
    deduplication took approximately 36-95 ms, sorting approximately
    1.7-1.9 ms, and pagination was negligible. These measurements establish a
    quantitative v0.6.0 reference rather than a historical performance
    comparison.
- [x] Investigate material regressions before release
  - Release validation identified result-window pagination regressions in DOAJ
    and Crossref. Both were fixed and revalidated in PR #93.

v0.6.0 must not be tagged or released until the required release-level
validation is complete or any accepted exception is explicitly documented.
