# LitSearch v0.7.0 Roadmap

## Goal

LitSearch v0.7.0 improves search precision by introducing identifier-based and bibliographic search capabilities.

The release builds on the stable v0.6.0 architecture and preserves the following principles:

- Centralized retrieval pipeline
- Uniform Paper model
- Centralized cross-source deduplication
- Connector-independent architecture
- Explicit source capability semantics
- Reproducible and transparent search behavior

## Release Scope

> **Scope decision (25 October 2026):**
> Author Search and Journal Search are explicitly excluded from
> the LitSearch development roadmap.
>
> LitSearch focuses on three search modes:
> - Literature Search
> - Identifier Lookup (DOI, PMID, PMCID)
> - Exact Title Search
>
> Author Search and Journal Search were evaluated but are not
> considered necessary for the application's primary purpose:
> transparent, reproducible scientific literature retrieval.
>
> The original requirements below are retained for historical
> traceability and do not represent active development commitments.

The primary focus of v0.7.0 is search functionality.

> **Release scope clarification (19 October 2026):**
> The scope below represents the original v0.7.0 development plan.
> The published v0.7.0 Pre-release delivers exact DOI, PMID and PMCID
> lookup. Bibliographic search (exact title, author and journal) was
> not delivered in the original pre-release.
> Exact Title Search was implemented and merged into main later.
> Author Search and Journal Search were subsequently cancelled
> and are no longer planned for development.
> The original requirements are retained for traceability.

Required scope:

- Identifier-based search: DOI, PMID, PMCID
- Bibliographic search: exact title
- Integration with existing retrieval and detail workflows
- Regression testing and release-level validation

Conditional scope:

- Publication type filtering
- Language filtering
- Open Access filtering

Conditional features require a capability assessment and explicit inclusion decision before implementation.

# 6. Deferred Beyond v0.7.0

## Planned Future Development

The following development areas are planned after completion
of the required v0.7.0 functionality and release validation:

- AI-assisted interpretation of retrieved literature
- Integration with BibQPrompt.com
- Authentication and user account management
- Subscription and access management
- Commercial SaaS deployment
- Paid literature search service workflows

AI-assisted interpretation must remain separate from the
deterministic retrieval pipeline and preserve source provenance,
transparency and reproducibility.

Commercial deployment requires completion of the Commercial
Production Gate.

## Deferred Without Implementation Commitment

The following features may be reconsidered in future releases
but are not currently approved for implementation:

- Institution and affiliation filtering
- Additional metadata enrichment providers
- Citation graph functionality
- New export formats
- Saved searches
- Full UI redesign

## Explicitly Out of Scope

The following features are excluded from the active development
roadmap:

- Author Search
- Journal Search
- BASE integration
- arXiv integration
- Additional scholarly retrieval source integrations

LitSearch remains limited to six retrieval sources:

- PubMed
- Europe PMC
- OpenAlex
- Semantic Scholar
- Crossref
- DOAJ

The development priority is improving the reliability, precision,
transparency and reproducibility of the existing retrieval
architecture rather than expanding the number of sources.

# 7. Development Principles

## Architecture and Scope

- Maintain the six existing retrieval sources.
- Preserve the centralized retrieval pipeline.
- Preserve the uniform Paper model.
- Preserve centralized cross-source deduplication.
- Reuse existing connector functionality.
- Avoid introducing duplicate retrieval logic.
- Respect source-specific capabilities and limitations.
- Keep deterministic retrieval separate from AI interpretation.

## Reliability and Reproducibility

- Preserve backward compatibility where possible.
- Ensure consistent search and export semantics.
- Preserve paper ordering and source provenance.
- Use snapshots where necessary to ensure consistency.
- Handle unsupported capabilities explicitly.
- Prevent silent fallback to alternative search modes.
- Document reproducibility guarantees and limitations.

## Development and Quality Assurance

- Use feature branches and pull requests.
- Write focused tests before implementing behavior.
- Prefer small, reviewable changes.
- Add regression tests for resolved defects.
- Validate changes in the running Docker application.
- Review skipped tests and document their reasons.
- Document important architectural decisions.
- Keep roadmap checkboxes aligned with verified implementation.
- Do not release with failing required CI checks.

## Commercial and Legal Compliance

- Consider commercial API licensing throughout development.
- Respect source-specific API terms and rate limits.
- Assess metadata reuse, storage and redistribution permissions.
- Assess compliance of caching and export functionality.
- Preserve required source attribution.
- Consider both SaaS subscriptions and paid literature search services.
- Protect user data and API credentials.
- Do not enable commercial production deployment before
  completion of the Commercial Production Gate.
